# Tariflow — техническое задание

Статус: спецификация и критерии реализации, 23.09.2026. Команда: Дима и Азим. Рабочее окно: **300 минут**. Фактическое состояние — STATUS.md и BASELINE.md.
Источники: `../PARTICIPANT_GUIDE.md` и `CHALLENGE_ORIGINAL.txt` с критериями оценки. Расписание — `WORK_PLAN.md`, интерфейсы — `ARCHITECTURE.md`, условия — `HACKATHON_RULES.md`.

## 1. Продукт

**Tariflow** (ранее ARPU Compass) — агент планирования тарифных кампаний: исследует аудиторию, проверяет гипотезы пилотами и распределяет бюджет с учётом риска потери выручки.

Пользователь — маркетинговый аналитик, планирующий кампании на следующий месяц. Результат: кому предложить тариф, какой тариф выбрать, через какой канал связаться и почему ожидаемая выгода оправдывает затраты.

Название рабочее для хакатона; проверка торговых марок не проводилась. Все данные синтетические: UI и README должны явно говорить об учебном кейсе, а не реальных показателях Beeline.

## 2. Состав результата

Обязательная поставка: корневой `agent.py` с классом `Agent`, методом `act(env) -> list[dict]`, воспроизводимый `submission.csv`, необходимые зависимости и README. CSV создаёт официальный `make_submission.py` из корня, где расположен импортируемый `agent.py`.

Веб — пользовательская оболочка для запуска анализа, просмотра фактического отчёта
и вопросов OpenAI с источниками. Он реализован отдельным локальным сервером и не
заменяет обязательные артефакты Agent.act/CSV. Независимый импорт JSON остаётся
резервным viewer. Расширение по запросу пользователя и зоны двух разработчиков
зафиксированы в NEXT_STAGE.md; HTTP-контракт — API.md.

## 3. Требования и приоритеты

| Приоритет | Функция | Приёмка |
|---|---|---|
| P0 | `Agent.act(env)` | Официальный evaluator завершается без исключения |
| P0 | Разведка через `run_pilot` | Хотя бы один успешный пилот; его результат влияет на выбор |
| P0 | 1–10 кампаний | Существующие тарифы/каналы, нет отброшенных кампаний |
| P0 | Контроль ресурсов | Все лимиты соблюдены, включая расходы и контакты пилотов |
| P0 | CSV | Создаётся официальной командой, воспроизводим при тех же входах/seed |
| P0 | README | Точные команды, версии, схема, ограничения и объяснение подхода |
| P1 | Исторические приоры | История ранжирует гипотезы, не подменяет эффект на целевой базе |
| P1 | Адаптивная разведка | Следующие гипотезы и размеры пилотов зависят от наблюдений |
| P1 | Устойчивость | 10 seed, минимум/медиана/разброс/доля отрицательных результатов, сравнение с baseline |

Не входят в MVP: GPU и обучение нейросети, реальные рассылки/CRM, авторизация, БД, Kubernetes, несколько независимых LLM-агентов. Условия не требуют мультиагентности. Честное описание: один агент с модулями анализа, эксперимента и распределения бюджета.

## 4. Сценарий

1. Аналитик запускает расчёт на выданной базе. Агент профилирует аудиторию и формирует гипотезы.
2. Агент проводит пилоты через публичный API среды и обновляет оценку полезности/надёжности.
3. После каждого наблюдения выбирает следующий эксперимент или переходит к распределению оставшихся ресурсов.
4. Агент возвращает 1–10 допустимых кампаний. Официальный evaluator считает результат, официальный генератор создаёт CSV.
5. Аналитик видит затраты, эффект, объяснение выбора и ограничения в CLI/веб-отчёте.
6. При отсутствии ключа или сети работает основная стратегия без LLM.

## 5. Данные и метрика

- Целевая база: `env.customer_profile` / `customer_profile.csv`, 23 441 абонент по заданию.
- Допустимые значения: `env.tariffs`, `env.channels`, справочники тарифов и признаков.
- История: `data/change_tariff.csv`; дополнительные таблицы — `traffic.csv`, `arpu_monthly.csv`, `dict_tariff.csv`.
- История описывает другую выборку. Сначала проверить идентификаторы/даты/уникальность; не соединять её с целевой базой по недоказанному совпадению ID.
- Эффект пропорционален `predicted_arpu`. Единицы результата пилота подтверждаем по публичному контракту; коэффициент канала не применяем дважды.
- Прирост считается по уникальным абонентам; стоимость — по всем контактам, включая пилоты и повторы. Базовую выручку показывать отдельно от чистого прироста.
- Мок-оценка проверяет механику и относительные сравнения, не предсказывает судейский балл.

## 6. Алгоритм

1. **Профилирование:** проверить колонки и значения, посчитать размеры сегментов и ARPU; исключить пустые аудитории и переход в текущий тариф.
2. **Кандидаты:** сформировать ограниченный пул «сегмент → тариф → канал» по истории, справочнику и ценности аудитории. Не фиксировать выигрышные `tariff_N`.
3. **Приоры:** оценить относительное изменение ARPU на корректных исторических парах; малые выборки сглаживать к общему среднему. Неполные данные дают слабый приор, а не падение.
4. **Разведка:** начать с разных информативных гипотез, затем уточнять перспективные/неопределённые. Размер 10–200 и не больше доступной аудитории. При отсутствии дисперсии возвращать эвристическую надёжность, не заявлять точный доверительный интервал.
5. **Обратная связь:** перечитывать остатки ресурсов после каждого пилота. Результат меняет последующее ранжирование. Учёт расходов не дублирует списания среды.
6. **Выбор:** максимизировать ожидаемую чистую выгоду с поправкой на неопределённость; учитывать охват и предельную пользу пересечений. По возможности финальные сегменты не пересекаются.
7. **Валидация:** проверить весь план до возврата. Если все оценки отрицательны, выбрать наименее рискованную допустимую кампанию по наблюдениям, учитывая обязательный минимум в одну кампанию; не обещать положительный эффект.

Параметры разведки определяются после baseline. Оставлять бюджет/контакты финальным кампаниям; не расходовать автоматически все 20 пилотов. Бесплатный push также расходует контакты и способен уменьшать ARPU.

## 7. Стек

| Часть | Выбор | Причина |
|---|---|---|
| Ядро | Python 3.12, pandas, NumPy, стандартная библиотека | Совпадает с интерфейсом DataFrame и доступным runtime |
| Оркестрация | Цикл observe → pilot → update → select | Прозрачен, ограничен по времени, автономен |
| LLM | OpenAI Responses API, stdlib HTTP + strict JSON schema | Два ограниченных совета; математика/лимиты в коде; автономный fallback |
| Веб | HTML/CSS/JavaScript, локальный сервер Python stdlib | Обзор, кампании, пилоты, вопросы; запуск и ответы по API, импорт JSON как резерв |
| Данные | Выданные CSV + JSON отчёта | Воспроизводимость без сервера БД |
| Проверка | Официальные CLI + точечные проверки контрактов | Соответствует проверке организаторов |
| Поставка | Командный GitHub и обязательные файлы | Публичный хостинг не заявлен обязательным |

Здесь доступны Python 3.12.14, pandas 3.0.1, NumPy 2.3.5; версии закреплены в requirements.txt. Азим проверяет окружение у себя. Ключ только в `OPENAI_API_KEY`. Начальная модель gpt-4.1-mini-2025-04-14 поддерживает Responses и structured outputs по официальной документации; OPENAI_MODEL позволяет заменить её. Значения ключей не входят в Git или браузер. Доступность для конкретного ключа отражается в отчёте фактического вызова.

## 8. Нефункциональные требования

- Цель исполнения <300 секунд; guide разрешает 600 секунд, шаблон говорит о 300 и отсутствии интернета. До уточнения соблюдать более строгий предел и автономный режим.
- Только публичный контракт среды и разрешённые входные CSV. Не исследовать закрытые эффекты и внутреннее состояние evaluator.
- Ограничить число LLM-вызовов и таймаут; отсутствие ключа, отказ/невалидный ответ/таймаут дают детерминированный fallback.
- Не изменять входную базу. Каждый запуск начинает собственное состояние; нет переноса пилотов между seed.
- В submission входят только допустимые поля; внутренние метаданные остаются в отчёте. JSON не содержит NaN/Infinity.
- UI показывает действия/наблюдения/результат; оценки отделены от измерений. Не выводить скрытые рассуждения модели.

## 9. Критерии готовности

**G1, T+60:** хотя бы один пилот, допустимая кампания, успешный официальный прогон и первый CSV.

**G2, T+150:** исторические приоры и пилотная обратная связь включены; модули двух разработчиков интегрированы; JSON отчёта стабилен.

**G3, T+220:** 10 прогонов без падений/нарушений, сравнение с шаблоном на одинаковых seed. Цель — улучшить медиану baseline без роста доли отрицательных результатов; если не достигнута, сохранить наиболее устойчивую проверенную версию и описать ограничение.

**G4, T+300:** запуск из чистого checkout по README, воспроизводимый CSV, файлы в GitHub, handoff и двухминутное демо. Веб принимается только при отображении реального прогона и проверке 375/768/1440 px.
