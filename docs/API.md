# Локальный API Tariflow — v1

Сервер: `server.py`. Ответы по отчёту: `report_assistant.py`.
Контракт реализован без дополнительных зависимостей. UI принадлежит Азиму.

## Запуск и транспорт

`python -X utf8 server.py --offline` или `python -X utf8 server.py --ask-key`.
Один адрес для UI и API: `http://127.0.0.1:8765`. Все frontend URL относительные.
Ключ читается из окружения сервера или скрытого запроса CLI; браузер его не получает.

Все POST требуют `Content-Type: application/json`, `Origin`, совпадающий с адресом
сервера, и `X-ARPU-Token` из health. Токен хранится только в памяти страницы.
CORS не включён. Тело запроса — объект JSON, максимум 16 КиБ.
Не принимаются произвольные команды, пути, ключи, модели, бюджеты и фильтры.

Ошибки: `{"error":{"code":"stable_code","message":"Понятное описание"}}`.
HTTP 400 — ввод; 403 — origin/token; 404 — объект отсутствует; 409 — операция уже
выполняется; 429 — частотный лимит; 503 — функция недоступна.
Ответы имеют `Cache-Control: no-store`. Сырые provider-ошибки и секреты не выдаются.

## GET /api/health

```json
{"api_version":"1.0","status":"ok","csrf_token":"opaque","openai":{"configured":false,"enabled":false,"model":"gpt-4.1-mini-2025-04-14"},"run":{"run_id":null,"state":"idle"},"capabilities":{"run":true,"chat":true,"chat_languages":["ru","kk"]}}
```

`configured` означает наличие ключа; `enabled` также учитывает `ARPU_OFFLINE`.
Это настройки, не доказательство успешного обращения к провайдеру.
`run.state`: idle/running/completed/failed. При idle идентификатор равен null.
После 403 обновить health и предложить повторить действие вручную.
Платные POST не повторять автоматически, даже при потере соединения.

## GET /api/report

200: `{"report_id":"opaque","report":{...report1.0...}}`.
404 `no_report`: сервер ещё не завершил свой первый расчёт.

Возвращает последний валидный снимок, скопированный в память сервера.
Старый `output/report.json` при старте не импортируется. Пользовательский импорт
JSON в браузере не получает server report_id и не отправляется в чат.
После ошибки расчёта предыдущий снимок сохраняется; не выдавать его за новый.

## POST /api/runs

Тело: `{"mode":"offline","seed":42}`. Ровно эти два поля.
`mode`: offline/openai. `seed`: целое число 0..4294967295, по умолчанию UI — 42.
OpenAI без enabled → 503 `openai_unavailable`; занятый расчёт → 409 `run_busy`.

202: `{"run_id":"opaque","state":"running"}`.
UI опрашивает статус раз в 1–2 секунды, отключает дублирующий запуск и показывает
реальную стадию. Проценты прогресса и промежуточные пилоты сервер не сообщает.

## GET /api/runs/{run_id}

```json
{"run_id":"opaque","state":"running","stage":"evaluating","mode":"offline","seed":42,"started_at":"2026-09-23T10:08:12.123456Z","finished_at":null,"report_id":null,"error":null}
```

- running: stage=evaluating; finished_at/report_id/error равны null.
- completed: stage=ready; finished_at и report_id заполнены, error=null.
- failed: stage=failed; finished_at заполнен; report_id=null; error={code,message}.

Время — ISO-8601 UTC с суффиксом `Z`. После успеха загрузить `/api/report` и
проверить совпадение report_id. При несовпадении не отображать чужой снимок как
результат ожидаемого запуска. Таймаут расчёта — 300 секунд.

## POST /api/chat

Тело: `{"report_id":"opaque","message":"Почему выбран этот канал?"}`.
Также допустимо необязательное поле `language`: `"ru"` или `"kk"`.
Без него язык — русский, прежний запрос полностью совместим.
Пример: `{"report_id":"opaque","message":"Қанша бюджет қалды?","language":"kk"}`.
Другие поля отклоняются; вопрос — 1–2000 символов после trim.
Неизвестный язык → HTTP400 `invalid_language`.
Клиент отправляет language только если health.capabilities.chat_languages его
объявляет; при работе со старым сервером отправляет прежние два поля и явно
сообщает, что ответы сервера пока доступны на русском.

Выбранный язык применяется к ответу, citations.label и warnings, включая
автономный fallback. Машинные refs, report_id, mode, числовые данные не переводятся.
Неизвестный снимок → 404 `report_not_found`; занятый ответ → 409 `chat_busy`.

```json
{"report_id":"opaque","answer":"Объяснение по фактам отчёта","mode":"openai","citations":[{"ref":"allocation.0","label":"План кампании 1"}],"warnings":[],"usage":{"input_tokens":0,"output_tokens":0}}
```

Каждый вопрос самодостаточен; сервер не обещает память предыдущих сообщений.
Ответ не меняет план, не выполняет инструменты и не запускает рассылки.
Режим запуска расчёта независим от режима ответов: при включённом серверном OpenAI
чат обращается к провайдеру, даже если сам отчёт получен автономно.
Без ключа/при сбое модели mode=offline, присутствует понятное предупреждение.
Если ответ модели отклонён проверкой структуры, ссылок или известной ошибки единиц
неопределённости, также возвращается mode=offline с отдельным предупреждением
о непрошедшей проверке. Известный usage провайдера при этом сохраняется.
Внешний вызов один, без повторов; timeout 20 секунд, максимум 1000 выходных токенов.
Frontend должен ждать минимум 30 секунд. Не считать timeout доказательством того,
что провайдер не обработал запрос.

Допустимые refs: evaluation, resources, planned_resources, allocation.0..9,
pilots.0..19, selection_diagnostics, forecast_summary. Последние два refs
доступны только при наличии соответствующих необязательных полей report1.0;
контракт — QUALITY_STAGE.md. Ссылка возможна только на данные текущего снимка.
Неизвестные refs нельзя делать кликабельными. answer/labels выводить через textContent.
Resources — остатки после пилотов; planned_resources — после выполнения плана.
Evaluation — измерение синтетического прогона, allocation — приблизительный прогноз.
Forecast_summary объединяет только финальные кампании; evaluation включает пилоты
и дедупликацию. Их разность не является ошибкой прогноза. Для типовых числовых
вопросов сервер формирует сводку из полей отчёта, а OpenAI получает эту же сводку
и источники для качественного комментария. Цифры в таком комментарии отклоняются;
пользователь получает автономную сводку с предупреждением и известным usage.

Usage содержит известные значения ответа провайдера. При сетевом сбое нули
означают отсутствие полученных данных о токенах, а не гарантию отсутствия расходов.
Не показывать точную стоимость в долларах без актуальной тарифной модели.

## Хранение, статические файлы и лимиты

Каждый расчёт создаёт `output/runs/<run_id>.json`. Сервер сверяет
`provenance.run_id`, seed, время, report1.0 и validation.valid, затем сохраняет копию.
Последние 10 снимков и 20 статусов хранятся только до перезапуска сервера.
Сам output игнорируется Git; корень репозитория/output/env не обслуживаются по HTTP.
Обычная CLI-команда экспорта без --run-id продолжает писать output/report.json.

Разрешены только index.html, styles.css, app.mjs, report.mjs, api.mjs, integration.mjs.
Новые статические пути согласовать с Димой; тесты и произвольные файлы не обслуживаются.
Bind только loopback. До 16 соединений, один расчёт и один ответ одновременно;
до 6 запусков и 12 вопросов в минуту. При переполнении соединений сокет закрывается.
Запуск дочернего процесса — фиксированный список аргументов без shell.
Offline-процесс не наследует OPENAI_API_KEY; Ctrl+C завершает активный расчёт.

### Контекст вопроса о кампании

Для явно названной кампании (например, «первая кампания», «1-я кампания» или
«кампания №1») сервер передаёт только её allocation и собственные завершённые
пилоты, совпадающие по гипотезе, каналу, цели и фильтрам. Общий evaluation исключён:
суммарный результат не подтверждает эффект отдельной кампании. Бюджет добавляется
при соответствующем вопросе. У каждой allocation есть внутренний список pilot_refs;
выходные citations ограничены фактически переданными источниками.
Списки и диапазоны номеров поддерживаются; отсутствующие номера отмечаются явно.
Автономное сравнение перечисляет все запрошенные кампании (до десяти в отчёте).
Вопрос о бюджете конкретной кампании показывает её расходы, а не подменяет их
остатком бюджета всего плана. Памяти прошлых вопросов нет: номер кампании нужно
включать в сам вопрос.
В контексте модели неопределённость передаётся как uncertainty_percentage_points:
значение4.3 означает4.3п.п. Связка «неопределённость4.3%» отклоняется и заменяется
автономным пояснением; эта ограниченная проверка не является полным fact-checker.
Свободный текст модели всё равно требует проверки по этим источникам: строгая схема
проверяет структуру и ссылки, а не доказывает истинность каждого предложения.

Текстовые номера пилотов берутся из отдельного number (с1), не из machine source_ref
(с0). Известная ошибка сдвига нумерации выявляется ограниченной проверкой явных
списков пилотов и вызывает такой же обозначенный offline-fallback.
