# План на 300 минут — Дима и Азим

T0 — начало работы по объявленному кейсу. Окно команды 5 часов; в исходном guide указано 9 часов. План не меняет официальный дедлайн. При позднем подключении Азим ориентируется на текущую контрольную точку, а не начинает свои 300 минут заново.

## Работа параллельно

| Время | Дима | Азим | Общий проверяемый результат |
|---|---|---|---|
| 00–20 | ТЗ, контракт, импорт пакета, базовая точка входа | Прочитать ТЗ/guide, поднять Python, подтвердить собственную зону | Одинаковая цель, исходники доступны обоим, роли и команды понятны |
| 20–60 | Рабочий Agent с пилотами/лимитами, evaluator, первый CSV | Изучить разрешённые CSV, описать схему/исторические пары, каркас candidate_model.py | G1: baseline и валидная отправка; CSV не ждёт UI/LLM |
| 60–105 | Адаптер пилотов, бюджет/контакты, отчёт JSON | Приоры переходов, сглаживание малых групп, генерация сегментов/кандидатов | Первый интегрируемый candidate_model.py; динамические кандидаты |
| 105–150 | Подключить приоры, адаптивное уточнение пилотов, выбор кампаний | Проверить data-модуль на реальных CSV и крайних случаях, закончить описание | G2: общая стратегия, результат пилотов меняет решения |
| 150–190 | Сравнить baseline/новую стратегию на одинаковых seed; исправить лимиты | Веб-экран импорта реального JSON: лимиты, пилоты, кампании, объяснения | Реальный результат отображается в браузере; видны ограничения |
| 190–220 | Прогон 10 seed, анализ проигрышей, фиксация лучшей устойчивой версии | README и воспроизведение в своём окружении; UI состояния | G3: таблица сравнений, нет нарушений/падений |
| 220–240 | Только при G3: один ограниченный LLM-советник либо улучшение стратегии | Только при G3: визуальная полировка, снимки 375/768/1440 | P2 берём только при запасе; T+240 feature freeze |
| 240–270 | Финальные evaluator/CSV, сверка состава репозитория | Чистый запуск по README, двухминутный сценарий, проверка ссылок/артефактов | Кандидат на сдачу и повторяемая демонстрация |
| 270–300 | Резерв на блокирующие исправления, final commit/push, артефакты | Репетиция демо, сверка README с реализацией и финальный handoff | G4: готовая поставка; последние 10 минут без новых функций |

## Правила переключения при отставании

- Нет G1 к 60-й минуте: оба решают совместимость/лимиты; приоры и UI откладываются.
- Нет G2 к 150-й: Дима сохраняет рабочую стратегию, Азим завершает один совместимый data-модуль; веб получает только просмотр отчёта.
- Нет G3 к 220-й: убрать LLM и дополнительную полировку из критического пути, сосредоточиться на исправлении падений/лимитов и документации.
- После T+240 принимаются только исправления сдачи, воспроизводимости и демо. После T+290 — проверка наличия файлов/пуша.
- UI может работать с сохранённым успешным отчётом: обязательно указать seed, время и что это сохранённый прогон. Не выдавать фикстуру за расчёт.

## Коммиты и синхронизация

1. Перед сессией и зависимой интеграцией: `git pull --rebase --autostash`.
2. Каждый владелец коммитит связанный законченный кусок с проверками примерно каждые 20–30 активных минут. Не коммитить ради таймера сломанный интерфейс.
3. Указывать конкретные изменённые файлы при checkpoint. Общие manifests/контракты интегрирует Дима; чужие личные заметки не менять.
4. После пуша в свой HANDOFF: SHA, законченная функция, затронутый контракт, что подключить и следующий шаг. Изменение интерфейса также записать в DECISIONS.
5. Второй разработчик перед зависимой задачей делает pull и читает handoff. Это обмен через Git, а не автоматическая передача истории Codex-чата.
6. При конфликте сохранять обе реализации/намерения, не force-push и не сбрасывать чужую работу. Неочевидное решение описать в QUESTIONS и перейти на независимую задачу.
7. Состав итоговой отправки проверяет Дима. Азим подтверждает воспроизводимость отдельным запуском и записью своего SHA/команды/результата.

## Стартовый промпт Азиму

> Работай как Azim в репозитории команды 1718. Убедись, что локальная .agent-identity содержит azim и исключена из Git. Выполни agent-sync и подтяни main. Прочитай docs/PROJECT.md, docs/WORK_PLAN.md, docs/ARCHITECTURE.md, PARTICIPANT_GUIDE.md и docs/agents/dima/HANDOFF.md. Твой первый приоритет — candidate_model.py и анализ только разрешённых CSV; контракт build_candidates описан в ARCHITECTURE. После интеграции G2 делай web/ и README. Не меняй agent.py, общий контракт, scripts/ и manifests без согласования с Димой. Подтверди свою зону только в своём разделе STATUS; работай параллельно и пушь небольшие проверенные коммиты с handoff. Никогда не исследуй скрытые эффекты или внутреннее состояние среды. Мок-оценка не является будущим судейским результатом.
