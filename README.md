# ARPU Compass

Агент тарифных маркетинговых кампаний для синтетического кейса Beeline на HackAlem AI, команда 1718 — Дима и Азим. Агент формирует гипотезы, проверяет их пилотами и возвращает план с учётом бюджета и контактов. Веб показывает фактический отчёт запуска. Все данные учебные; реальные рассылки не выполняются.

## Быстрый запуск

Из корня репозитория, Python **3.12**:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -X utf8 scripts/run_agent.py --offline
python -m http.server 8080 --bind 127.0.0.1 --directory web
```

Откройте [локальный интерфейс](http://127.0.0.1:8080), нажмите «Открыть отчёт» и выберите `output/report.json`. Это сохранённый фактический прогон, а не новый расчёт в браузере. Для следующего расчёта повторите `run_agent.py` и импортируйте новый файл. Сервер останавливается `Ctrl+C`.

Linux/macOS: активируйте окружение командой `source .venv/bin/activate`. Зафиксированы pandas 3.0.1 и NumPy 2.3.5. `-X utf8` обеспечивает корректный вывод русских сообщений в Windows. Для веба не нужны npm, внешние шрифты, сервер API или интернет. Файл читается локально в браузере.

## Что показывает отчёт

- Измеренный чистый прирост — только `evaluation.net_arpu_gain` из публичного evaluator. Отрицательный результат остаётся отрицательным; `PASS` одного прогона не доказывает устойчивость.
- Бюджет и контакты после пилотов (`resources`) и после запланированных кампаний (`planned_resources`) показаны отдельно. Нет поля — нет данных.
- Пилоты: сегмент, целевой тариф, канал, фактический размер, наблюдённый эффект и доступная стоимость. Прогнозы из `allocation` явно обозначены.
- Кампании: выражаемые фильтры, тариф и канал. CSV-экспорт экрана — вспомогательный; официальный `submission.csv` создаётся командой ниже.
- Предупреждения, ограничения, seed и время сохранённого прогона. При ошибке JSON можно выбрать файл повторно; пустой план не изображается готовым.

Поддерживается `schema_version: "1.0"` из [ARCHITECTURE](docs/ARCHITECTURE.md). Опциональные поля могут отсутствовать. Экспортёр проверяет план перед атомарной записью; дополнительные `provenance` и `validation` совместимы с интерфейсом. До импорта интерфейс не показывает выдуманных результатов.

## Официальные проверки и отправка

```powershell
$env:ARPU_OFFLINE = '1'
python -X utf8 local_eval.py
python -X utf8 local_eval.py --runs 10
python -X utf8 make_submission.py
python -X utf8 -m unittest discover -s analysis -v
python -X utf8 analysis/audit_public_data.py
```

Проверки веб-модуля (если установлен Node.js): `node --test web/report.test.mjs`.
Никакие npm-пакеты для них не требуются. Проверены импорт фактического JSON,
ошибки/повторный выбор/пустой план, отрицательные и отсутствующие метрики,
CSV, клавиатура и экраны 375/768/1440 px. Локальные снимки — `output/playwright/`.

Для Linux/macOS вместо строки PowerShell: `export ARPU_OFFLINE=1`. Обычный evaluator и генератор CSV используют seed 42; `--runs 10` — seed 0…9. `make_submission.py` создаёт официальный корневой `submission.csv` с семью колонками. После интеграции новой стратегии его нужно создать заново; общий артефакт ведёт Дима. Скрипты организаторов импортируют `from agent import Agent`, аргумента `--agent` нет. Исходные CSV включены в репозиторий.

Техническая проверка: `pwsh ./scripts/verify.ps1`. При отсутствии подходящего Python в PATH задайте `ARPU_PYTHON` путём к Python 3.12. Проверка запуска и лимитов отделена от экономического качества. Инструкции сравнения контроллеров и отложенной серии — в [RUNBOOK](docs/RUNBOOK.md).

## Подход и проверенные результаты

`profile + разрешённая история → кандидаты → пилоты → обновлённые оценки → план`

`candidate_model.py` принимает ровно три аргумента: `profile`, `tariffs` (DataFrame), `data_dir`. Он строит ограниченный пул переходов по текущему тарифу и ARPU/data/call-сегментам. Цена и пакеты помогают предложить цель, но не подменяют оценку изменения выручки. Размер и сумма ARPU соответствуют точным фильтрам; нельзя обрезать группу и заявить меньшую аудиторию.

История описывает другую выборку: ID не соединяются с целевой базой. Приоры строятся по паре тарифов и историческому ARPU-сегменту, сильно сглаживаются к нулю и ограничены ±2,5%. LOW, мало наблюдений и противоречивый сигнал дают нулевой приор. Подробности и воспроизводимые числа — в [analysis/README.md](analysis/README.md). Реальные пилоты имеют приоритет; результат одного канала не выдаётся за измерение другого.

Проверенная интеграция: кандидаты **f740180**, ядро **92872b5**, экспортёр **678eb7b**, веб **593667d**, offline:

| Проверка | Результат |
|---|---:|
| Контракт кандидатов | 7/7 тестов |
| Кандидаты / выражаемые сегменты | 299 / 160 |
| Seed 42: net / пилоты / финальные кампании | +685 150 у.е. / 20 / 3 |
| Seed 42: затраты / контакты | 46 598 у.е. / 5 606 |
| После плана: бюджет / контакты | 53 402 у.е. / 9 394 |
| Веб-модуль | 8/8 тестов; браузер 375/768/1440 |

Это mock-измерения, не прогноз судейского результата. По журналу Димы для ядра 92872b5 девять новых seed 40, 41, 43…49 дали 9/9 положительных результатов, медиану +657 090 против +582 083 у предыдущей версии, минимум +515 723 против +505 527. Контрольный seed 42 исключён из этих девяти. Выборка мала; общее уменьшение риска не доказано. Воспроизведение и старые измерения — в [BASELINE](docs/BASELINE.md). Текущий статус — в [STATUS](docs/STATUS.md); таблица привязана к указанным версиям, а не ко всем будущим изменениям `main`.

## OpenAI и автономный режим

Основной расчёт работает без ключа и сети. Чтобы использовать настроенный `OPENAI_API_KEY` из окружения, запустите `python -X utf8 scripts/export_report.py`. `OPENAI_MODEL` выбирает модель. `ARPU_OFFLINE=1` принудительно запрещает запросы. Для скрытого ввода ключа только на время одного процесса:

```powershell
python -X utf8 scripts/run_agent.py --ask-key
```

Советник получает агрегаты кандидатов и даёт не более двух ограниченных советов. При ошибке, таймауте или отсутствии ключа используется автономная стратегия. Статус `adaptive-openai` означает принятый совет, не доказанный вклад LLM в прибыль. Ключи не передаются в браузер, файлы, параметры командной строки или Git. Официальную воспроизводимую отправку генерируем с `ARPU_OFFLINE=1`.

## Ограничения и работа команды

Не более 10 финальных кампаний, 5 000 абонентов на кампанию, 15 000 контактов, 100 000 у.е. и 20 пилотов по 10–200 клиентов; пилоты входят в общие расходы. Повторные контакты стоят ресурсов. Обязательный минимум в одну кампанию может привести к явно отмеченному fallback. Приблизительная оценка неопределённости не является калиброванным доверительным интервалом.

Guide разрешает 10 минут и LLM; комментарий шаблона говорит о 5 минутах и отсутствии интернета. До уточнения поддерживаем автономную работу менее 5 минут. Скрытые эффекты среды не исследуются; пакет организаторов не меняется.

Дима ведёт ядро, пилоты, распределение, scripts/ и контракты. Азим — candidate_model.py, analysis/, web/ и README. `.agent-identity` содержит локально `dima` или `azim` и исключена из Git. Примерно каждые 4 активные минуты сверяем main и handoff; перед зависимой интеграцией выполняем `git pull --rebase --autostash`. Во время серии оценок сначала ждём её окончания. Законченные проверенные части публикуем через checkpoint с явным списком:

```powershell
& ./scripts/checkpoint.ps1 'feat: improve candidate priors' -Paths @('candidate_model.py', 'analysis/README.md')
```

Скрипт проверяет, коммитит, синхронизирует, повторно проверяет и пушит; при ошибке останавливается. Общие вопросы — в [QUESTIONS](docs/agents/shared/QUESTIONS.md), текущие передачи — [Дима](docs/agents/dima/HANDOFF.md) и [Азим](docs/agents/azim/HANDOFF.md).
