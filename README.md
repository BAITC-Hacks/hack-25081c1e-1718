# Tariflow

Tariflow помогает маркетинговому аналитику выбрать тарифные кампании для следующего месяца: **исследовать аудиторию → провести пилоты → обновить оценки → собрать план** в пределах бюджета и лимита контактов. Это решение учебного синтетического кейса HackAlem AI; оно не отправляет сообщения абонентам и не измеряет реальную прибыль Beeline.

**С чего начать:** [запуск и официальная проверка](#запуск-из-чистого-checkout) · [подход](#как-работает-агент) · [подтверждённые результаты](#подтверждённые-результаты) · [двухминутное демо](docs/DEMO.md) · [ограничения](#ограничения-и-развитие).

## Что сдаём

- `agent.py` с классом `Agent` и методом `act(env) -> list[dict]`: 1–10 кампаний с допустимыми фильтрами, тарифами и каналами.
- `submission.csv`, созданный официальным `make_submission.py` из корня проекта. Экспорт CSV из веб-интерфейса служит для просмотра и не заменяет его.
- `requirements.txt` с зависимостями и этот README с воспроизводимым запуском. Для загрузки отдельными файлами сборщик готовит `output/submission/agent.py`, `submission.csv`, `requirements.txt`; подробности ниже.

Публичные CSV кейса находятся в репозитории и нужны во время локальной проверки. В архив сдачи они не включаются: среда организаторов предоставляет свои публичные входные файлы. Канал и дедлайн загрузки команда уточняет; наличие готового пакета не подтверждает отправку.

## Запуск из чистого checkout

Целевой runtime — Python **3.12**; проверьте версию до установки. Команды ниже выполняются в корне чистого checkout. Node.js нужен только для веб-тестов, npm-пакеты не нужны.

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:ARPU_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
$env:ARPU_OFFLINE = '1'
& $env:ARPU_PYTHON -X utf8 local_eval.py
& $env:ARPU_PYTHON -X utf8 local_eval.py --runs 10
& $env:ARPU_PYTHON -X utf8 make_submission.py
pwsh -NoProfile -File ./scripts/verify.ps1 -Release
& $env:ARPU_PYTHON -X utf8 scripts/package_submission.py
```

В Linux/macOS используйте `python3.12 -m venv .venv`, затем `.venv/bin/python` вместо Windows-пути и `export ARPU_OFFLINE=1`; для `verify.ps1` задайте `ARPU_PYTHON` путём к этому интерпретатору. `-X utf8` сохраняет читаемый русский вывод в Windows. `local_eval.py` — официальный evaluator: одиночный вызов использует seed 42, `--runs 10` — seed 0–9. Официальный генератор создаёт корневой `submission.csv` с семью колонками. `verify.ps1 -Release` проверяет контракт, официальный запуск и CSV; экономическая устойчивость проверена отдельно. Если команда `python` указывает на другую версию, запустите установленный Python 3.12 по полному пути при создании `.venv`.

После успешного `-Release` сборщик создаёт `output/submission/` и `output/submission.zip`. Для отдельной загрузки берите файлы из `output/submission/`: standalone `agent.py` включает собственные модули кандидатов и советника, так что внешние `candidate_model.py` и `llm_advisor.py` для него не нужны. ZIP также содержит этот README, краткий `SUBMISSION.md`, связанные продуктовые документы и справочный manifest с версиями, хешами и точным списком файлов. Логи команды, веб-сервер, локальные `output` и публичные входные CSV туда не входят. Сборщик не запускает evaluator и не обновляет CSV, поэтому порядок команд важен. [Полный порядок и проверки](docs/RUNBOOK.md).

### Локальный интерфейс

```powershell
python -X utf8 server.py --offline
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765), оставьте автономный режим и нажмите **«Запустить анализ»**. Seed по умолчанию — 42. После запуска сервера снимка ещё нет; кнопка «Открыть последний расчёт» покажет отчёт только после завершённого прогона. Сервер хранит последний валидный отчёт в памяти, файл прогона — в `output/runs/`. Остановка — `Ctrl+C`.

Для независимого просмотра без API:

```powershell
python -X utf8 scripts/run_agent.py --offline
python -m http.server 8080 --bind 127.0.0.1 --directory web
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080) и импортируйте `output/report.json`. Импортированный файл остаётся в браузере; запуск и вопросы требуют сервера на 8765 и его собственного ID отчёта. Ошибка API не превращает файл в «новый прогон».

## Как работает агент

Один `Agent` объединяет модули профилирования, кандидатов, эксперимента, советника и выбора плана. Это не система независимых агентов и не средство реальной рассылки.

1. Профиль целевой базы и публичная история переходов формируют выражаемые гипотезы «сегмент → тариф → канал». Исторические ID не соединяются с целевой базой: это разные выборки. Приоры сглаживаются и уступают наблюдениям пилотов.
2. `Agent.act` запускает пилоты через публичный `env.run_pilot`, читает фактические размеры, эффект и оставшиеся ресурсы после каждого шага. Следующая гипотеза зависит от уже увиденного. В обычной стратегии размер пилота выбирается по фиксированным этапам 150/200, а не непрерывно подстраивается под данные.
3. Для финального варианта используется эффект собственных пилотов **того же канала**. Оценка выручки уменьшается на коммуникационные расходы и эвристический запас неопределённости. Система учитывает перекрытие аудитории, бюджет и контакты, включая уже израсходованные пилотами. Если положительного допустимого набора нет, обязательный минимум в одну кампанию оформляется как явный fallback.
4. План из 1–10 кампаний проверяется перед возвратом. Официальный evaluator считает фактический результат синтетической симуляции; прогноз кампаний и его итог не подменяют друг друга.

При доступном OpenAI Responses API ограниченный советник даёт до двух советов: до первых пилотов и после обратной связи. Он предлагает приоритеты гипотез, но не меняет математические ограничения. Ключ, отказ, таймаут или некорректный ответ не останавливают автономный расчёт. Чтобы ввести ключ скрыто на время локального процесса, используйте `python -X utf8 server.py --ask-key` или `python -X utf8 scripts/run_agent.py --ask-key`. Альтернатива — `OPENAI_API_KEY` в окружении; `OPENAI_MODEL` задаёт модель, `ARPU_OFFLINE=1` отключает сетевой совет. Ключ не вводится в браузер и не сохраняется в файлы.

Архитектура и границы модулей: [ARCHITECTURE](docs/ARCHITECTURE.md), [PROJECT](docs/PROJECT.md), [API](docs/API.md). История и аудит входов: [analysis/README](analysis/README.md).

### Чем отличается решение

Гипотезы опираются на публичные признаки, а пилоты реально меняют выбор следующей проверки и финального плана. Финальная оценка использует собственные наблюдения варианта и канала, а не смешивает результаты разных каналов. План учитывает уже потраченные пилотами бюджет и контакты, перекрытие аудиторий и запас неопределённости. Отчёт раскрывает причины исключения и источники каждой кампании. Сетевой советник необязателен и ограничен двумя запросами; автономный путь остаётся воспроизводимым.

## Что видно в веб-отчёте

Интерфейс работает на русском и казахском. Переключение сохраняет отчёт, фильтры и черновик; исходные ID, названия кампаний, числовые значения и старые ответы не переписываются. Пакеты и месячные цены берутся из публичного `tariff_dictionary.csv`. **Ден. ед. — условные денежные единицы:** валюта в данных не задана.

Обзор показывает `evaluation.net_arpu_gain` как измеренный прирост выручки после коммуникационных расходов всей синтетической симуляции. Остатки после пилотов (`resources`) отделены от плановых остатков после финальных кампаний (`planned_resources`). «Что исследовал агент» различает созданные и исследованные гипотезы от вариантов гипотезы с каналом; показывает повторные пилоты, выбранные варианты, расходы пилотов и причины исключения. Повторная проверка не означает положительный эффект. Карточка кампании ведёт только к собственным завершённым пилотам её канала и раскрывает оценку, разброс, метод и эвристический запас. Сумма размеров пилотов не объявляется числом уникальных людей.

`forecast_summary` оценивает **только финальные кампании**; `evaluation` измеряет **пилоты и финальные кампании с дедупликацией**. Разницу между этими суммами нельзя считать ошибкой прогноза. Старый report 1.0 без новых необязательных полей показывает «нет данных»; браузер не восстанавливает пропуски выдуманными числами. Ссылки ответа агента открывают только существующие данные текущего серверного снимка. Вопросы не обладают памятью истории и не меняют план; OpenAI, автономный ответ и отказ помечаются по фактическому режиму. [Контракт диагностик](docs/QUALITY_STAGE.md), [решения по дизайну](docs/DESIGN.md).

Новый проверенный отчёт Димы фиксирует чистую поставку на **`9a1b3b1`** (Python 3.12.14, pandas 3.0.1, NumPy 2.3.5): `verify.ps1 -Release` PASS, **69 Python**, **7 analysis** и **33 Node** теста PASS. Отдельно собранный самостоятельный `agent.py` без внешних helper-модулей дал на официальном seed 42 точно **685149.5196317472** условных денежных единиц net, совпал с модульным агентом, а их официальные CSV совпали побайтно. Это результат синтетической симуляции на указанном Git-снимке, а не обещание для скрытой оценки. [Команды, исходный SHA и хеши](docs/quality/followup-release.json).

На заранее отделённых seed **300–319** медиана baseline составила **674970.62**, адаптивного размера пилота — **642092.75**; оба получили положительный net в 20/20 запусках, но адаптивный вариант улучшил только 8 пар и ухудшил 12. У него ниже p10 (**494131.63** против **529955.35**) и парная медиана изменения **−12446.91**. Заранее заданный gate не выполнен, поэтому обычный `Agent()` остаётся **baseline/template/fixed**. Вместе с разработческой серией 200–209 это 110 новых сравнительных запусков; неудачные варианты и все исходы сохранены, параметры после независимой серии не подбирались. ## Ограничения и развитие

Данные и evaluator синтетические. Их net показывает результат конкретной симуляции, а не коммерческий результат или «точность детекции»; размеченной правильной классификации нет. Оценка неопределённости эвристическая и не является калиброванным доверительным интервалом. Финальный эффект OpenAI не установлен на широкой выборке; свободный текст модели не имеет универсальной гарантии достоверности. Обязательные критерии, доказательства и открытые риски перечислены в [JUDGING_AUDIT](docs/JUDGING_AUDIT.md); балл жюри и отправка организаторам не подтверждены.

Дальше: проверять новые гипотезы на новых заранее отделённых seed и разрешённых сценариях данных; калибровать оценки неопределённости; после отдельного разрешения валидировать с реальными бизнес-ограничениями без настоящих рассылок из этого интерфейса.
